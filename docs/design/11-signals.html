Signals — a self-hosted Sentry that lives in the sidebar, not a dashboard

External apps send signals (error · log · event) to a local daemon; error signals group by fingerprint into issues (open / resolved / ignored), and every signal carries a session_id so a session is the full chronological trail of one page load. Everything reuses Instrument: table, badge, tab, and toolbar patterns from Tickets and AI Sessions; issue status inherits the status-kind shapes (open = half circle, resolved = filled + check, ignored = dashed) so state reads without color, and a regression rides next to open as an orange ↺ chip rather than replacing it. Levels are shape-coded dots, counts are grouped-thousands mono and never abbreviated — a flood must read as a flood — and the local-first posture is worn openly: the DSN points at 127.0.0.1, the footer reports disk retention, and the error state blames the daemon, not “the cloud.” Screens A–D below in light + dark: Apps (with the new-app DSN panel and fresh-install empty state), Issues (the workhorse, plus loading / error / empty), Issue detail (symbolicated and raw), and the Session timeline.
