# bh reuse audit — 2026-10-11

What bh duplicates inside itself, what the apps that copy bh rebuild on their own, and which components fuse a behaviour with a view (the `CopyButton` problem). Read-only: nothing was changed.

Scope: every bh package plus `apps/docs`, and the 9 apps that vendor bh: cv, gateway, icon-editor, items-core, medialib, session-board, signals, tickets, wallet-passes. (`cv-dynamic-profiles` and `cv-generic-io` are git worktrees of cv on the branches `dynamic-profiles` and `hosted-extension`, not apps.)

App paths are relative to that app's repo. bh paths are relative to the bh repo (a sibling of this one).

## 1. CopyButton, and the rule behind it

### CopyButton

[copy-button.tsx](packages/web/ui/src/library/primitives/components/copy-button/copy-button.tsx) exports two things:

- `useCopy`, the behaviour: write to the clipboard, then hold `copied` or `failed` for 1.5 s.
- `CopyButton`, a raw `<button>` whose classes (lines 61-70) re-spell `Button`'s outline/sm look by hand.

Copying is a hook; the view should be `Button`. Many places already do it that way:

```tsx
const { copy, copied } = useCopy();
<Button variant="ghost" onClick={() => copy(text)}>
  <Icon name={copied ? 'check' : 'copy'} />
</Button>
```

**Where `<CopyButton>` is used** (counted by grep, outside the vendored copies):

| Where | Uses | Sites |
|---|---|---|
| bh | 3 | [code-block.tsx:41](packages/web/code/src/code-block/code-block.tsx:41) (so every CodeBlock, markdown `code` block, ref block and props doc too), [variants-views.tsx:459](apps/docs/src/blocks/variants-views.tsx:459), [page-actions.tsx:58](apps/docs/src/page/page-actions.tsx:58) — which duplicates a `useCopy` + `Button` copy for the same markdown four lines earlier |
| items-core | 8 | 4 are copyable-id chips (`crawl-profile-overview-card.tsx:26`, `obstacle-parsed-tab.tsx:40`, `pattern-overview-card.tsx:57`, `sitemap-parsed-tab.tsx:104`); `lib/raw-text-card.tsx:23` |
| wallet-passes | 6 | dashboard |
| signals | 2 | `dsn-field.tsx:21`, `sdk-snippet.tsx:68` |
| gateway | 1 | `tokens-page.tsx:45` |
| cv | 1 | `workspace/parts.tsx:36` (JsonBlock) |

**Already `useCopy` + a plain button:** 8 files in bh (`edit-bar.tsx:133`, `width-tweak.tsx:63`, `example-panel.tsx:800`, `page-actions.tsx:41`, `variants-views.tsx:101`, `json-viewer.tsx:168`, …), plus signals `session-screen.tsx:169`, tickets `item-detail.tsx:111` and icon-editor `source-panel.tsx:353`. Three of these have their own small gaps:

- bh's docs sites ignore `failed`, and use lucide `Check`/`Copy` instead of `Icon`.
- json-viewer feeds the hook into a private raw-button `ToolButton` (`parts/tool-button.tsx:18`).
- icon-editor's copy button is a raw `<button>`.

**Also:** `@bh/table`'s cell copy calls `navigator.clipboard?.writeText` directly ([use-cell-focus.ts:284](packages/web/table/src/use-cell-focus.ts:284)): a failure is silent and there is no feedback. table cannot import ui, so it needs an `onCopyCell` prop that ui's `tableRender` fills.

**Steps:**

1. Move `useCopy` into its own module, and add a plain `copyText(text): Promise<boolean>` for non-React callers.
2. Give `Button` an icon-only size (see 2.1). CodeBlock's copy needs one.
3. Rewrite the 3 bh sites, the 2 examples, and the docs that recommend CopyButton (including `button.md:141`).
4. Delete `CopyButton` as `feat(ui)!:`.
5. Change the 18 app sites as each app takes the update; its checks will fail until they are changed.

## 2. Where bh falls short, so the apps build their own

Most of the duplication in the apps follows one pattern. bh's component lacks one thing, so the app writes its own, and that copy then drifts. Filling these gaps lets the most app code be deleted.

| # | What bh lacks | Apps that built their own | Fix in bh |
|---|---|---|---|

| 2.2 | **relative time** finer than a day, a **date-time** format, and a **locale** | gateway `agoOf`; medialib `RelativeTime` (28 uses); signals; items-core 7 `toLocale*`; wallet-passes 4 copies (the reason given: RelativeDate is English only); cv `formatTimestamp` (20 uses); tickets; session-board; icon-editor | minute and hour steps in `relativeLabel`/`RelativeDate`, `formatDateTime`, a `locale` option, and an exported `useNow` |

## 6. Suggested order

1. **Remove CopyButton.** Give `useCopy` its own module and `copyText`, and add the icon-only Button size, since CodeBlock's copy needs it. One `feat(ui)!:` release.
2. **Export the private helpers.** `readStored`/`writeStored` + `usePersistedState`, `useMediaQuery`, the contrast maths, one `formatBytes`, and the date formatters. Low risk; it lets 6+ apps delete copies.
3. **Fill the gaps** in section 2:
   - RelativeDate granularity and `formatDateTime`
   - `Notice`
   - Button `link` + `href`
   - ScreenState loading
   - async ConfirmDialog
   - TabNav longest match
   - FieldWrapper stacked layout
   - rich radio and checkbox options
4. **Add the behaviour hooks:** `useDisclosure`, `useInlineEdit`, `useConfirm`, `useElementSize`, `useDebounced*`, `useNow`, `useControllableOpen`, `useDrag`.
5. **Do the internal merges** in section 3: Dot, Popup/Dropdown, FieldTrigger, Calendar, Select/Combobox, the Slider track, and Tabs' segment mode.
6. **Add components 3+ apps want:** Stat, DescriptionList, Sparkline, `useSortedTable`, Kbd, Skeleton, PageBody (and LogView, task 16).
7. **Migrate each app** when it takes the release; fix wallet-passes' `Prose` import first.
